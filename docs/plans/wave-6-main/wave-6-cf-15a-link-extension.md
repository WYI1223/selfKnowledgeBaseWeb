## decision-log

### Decision 1 — `openOnClick: false`

Tiptap's Link extension defaults to `openOnClick: true` which
makes anchor clicks navigate the browser — disastrous in an
edit surface (clicking a link in the editor would take you away
from `/notes/{slug}/edit`). `openOnClick: false` makes anchors
visually distinct (Tiptap still applies link styling) but
non-navigable on plain click. Users who want to follow a link
can ctrl-click / right-click → "Open in new tab" the same way
any other in-page anchor works.

### Decision 2 — Split from #15b (block-Code rename)

The original #15 spanned ~15 files (block-Code core, mdx-bridge
dispatch, registry-wire BlockKindOption literal types, ~6
test files asserting `'code'` kind, plus the Link addition).
Splitting:
- #15a (this PR) — Link registration + sanitizer relaxation +
  vitest round-trip cases + sample-blocks Playwright assertion
  + editor-shell CONTRACT.md sister-doc sync; 8 files total
  (originally drafted as ~5 then expanded by R1 + R4 fold-ins).
  Touches the editor-shell public-surface CONTRACT (Row 1 fires;
  stage 4 triggered) but the change is additive (extensions stack
  + new optional `extensions` prop) — no breaking signature
  change.
- #15b (separate) — cross-package rename; touches the BlockKind
  type union literal `'code'` → `'componentCode'` (or
  equivalent), updates ~10 test files, requires a CONTRACT.md
  amendment in `@skb/block-code` and possibly `@skb/editor-shell`.

This way the bigger refactor doesn't block the smaller fix
shipping; the user sees links rendering in the editor today,
inline-code-mark restoration ships separately when #15b lands.

### Decision 3 — Link config: extended `title` attr + `openOnClick: false`

Tiptap's default `Link` accepts `href`, `target`, `rel`, and
`class` but NOT `title`. mdx-bridge already emits `title` on
the link mark when a markdown link uses the
`[text](url "title")` form (parse.ts emits → serialize.ts
consumes), so a default Link configuration would have dropped
`title` on `setContent` and titled markdown links would have
lost data on edit/save. The fix is `Link.extend({
addAttributes: { title: ... } })` with `parseHTML` reading the
`title` HTML attr and `renderHTML` emitting it back when
present (R1.1 fold-in). On top of the extended class,
`.configure({ openOnClick: false })` keeps anchor clicks
inside the editor from navigating away from `/notes/{slug}/edit`
(users can still ctrl-click / right-click to open externally).
Other defaults (`autolink: true`, `linkOnPaste: true`, default
URL validation; `protocols` defaults to `[]` and is left
unconfigured because the markdown corpus only emits
http/https/mailto URLs which the default validator already
accepts) are reasonable for the current corpus. Out of scope: anchor click-through to
internal `/notes/{slug}` routes (would require route-aware Link
variant), security review of external URL allowlist (Phase 2+
if/when notes are user-shareable).
