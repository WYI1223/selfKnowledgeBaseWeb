# Pre-A1 — codex profile TOML merge documentation (runbook prose)

> **Wave 3 main pipeline first PR.** Tiny scope (single doc-prose addition + regen)
> chosen deliberately to exercise the ADR-0011 D1 6-stage pipeline end-to-end on
> low-risk material before Stage A's larger PRs. Bootstrap-flavored: the PR
> documents a step that future sessions need so the new D6 codex profiles
> (`generic-executor` etc.) become invocable; until the user runs the documented
> merge, the D1 stage 3 review continues to use the transitional `pr-gate` alias.

## title

Add a "Profile TOML merge (session start)" section to the codex tool invocations
runbook so future Claude sessions prompt the user to merge `tmp/codex-profiles.toml`
→ `~/.codex/config.toml`, exposing the 7 ADR-0011 D6 codex profiles.

## test_cases

Pre-A1 is pure documentation prose; the "tests" are deterministic generator +
the documentation-acceptance assertions that the new prose section is structurally
correct, plus the standard repo-hygiene gates.

- **TC1** (documentation-acceptance, in-repo) Input: read
  `docs/runbooks/codex-tool-invocations.md` after `pnpm generate:configs`.
  Expected: contains a section header `## Profile TOML merge (session start)`
  positioned **before** `## Single-source-of-truth lineage`; the section body
  contains (a) the literal verification command
  `grep '^\[profiles\.' ~/.codex/config.toml | sort` inside a fenced
  ` ```bash ` block, and (b) the 7 expected profile names listed verbatim:
  `codex-pr-reviewer-55`, `generic-executor`, `mdx-doctor`, `perf-auditor`,
  `plan-challenger`, `scaffolder`, `structure-auditor` (sorted as in
  `tmp/codex-profiles.toml`). Location: `grep -nE '^## (Profile TOML merge|
  Single-source-of-truth lineage)' docs/runbooks/codex-tool-invocations.md`
  shows the new heading on a line number lower than the lineage heading.
- **TC1'** (user-side post-merge verification, OUT-OF-PR-SCOPE — this is what
  the new prose *documents*, not what this PR runs) Input:
  `grep '^\[profiles\.' ~/.codex/config.toml | sort`. Expected: 7 lines listing
  the same 7 profiles above. Location: user's interactive shell after merging
  `tmp/codex-profiles.toml` into `~/.codex/config.toml`. Recorded here for
  acceptance traceability only; the PR cannot run this against the user's
  machine.
- **TC2** (idempotency) Input: `pnpm generate:configs && git status --short`.
  Expected: empty (zero diff on second run; CI invariant per
  `.github/workflows/agent-contract-check.yml`). Location: shell at repo root.
- **TC3** (typecheck) Input: `pnpm typecheck`. Expected: exit 0 (renderer edit
  must compile; the `HEADER` template-literal change is plain string work but
  WE-013 escape rules apply — see "Out-of-scope" below for the WE-013 caveat
  reminder). Location: shell at repo root.
- **TC4** (lint) Input: `pnpm lint`. Expected: exit 0, no warnings. Location:
  shell at repo root.
- **TC5** (size-check) Input: `pnpm size-check`. Expected: exit 0; no source
  file ≥ 500 lines. (`scripts/render/codex-tool-runbook.ts` is currently ~100
  lines; the new HEADER section adds ≤ 30 lines and stays well under the
  limit. The regenerated runbook is also far under 500.) Location: shell at
  repo root.

## acceptance

1. The rendered `docs/runbooks/codex-tool-invocations.md` opens with a new
   `## Profile TOML merge (session start)` section positioned **before**
   `## Single-source-of-truth lineage`. The section explains: (a) why the merge
   is needed (D6 introduced 4 NEW profiles + renamed `pr-gate` → `codex-pr-reviewer-55`;
   `~/.codex/config.toml` from Wave 1+2 era does not yet contain them); (b)
   how to perform the merge (manually copy each `[profiles.<name>]` block from
   `tmp/codex-profiles.toml` into `~/.codex/config.toml`, preserving order and
   not overwriting unrelated user-local profiles); (c) how to verify with
   `grep '^\[profiles\.' ~/.codex/config.toml | sort`; (d) the 7 expected
   profile names listed verbatim.
2. The authority `scripts/render/codex-tool-runbook.ts` `HEADER` constant is
   the only hand-edited renderer file; WE-013 backtick-escape pattern in
   the template-literal is preserved (mirror existing fence pattern at lines
   31-33 of the renderer).
3. `pnpm generate:configs` runs to completion; second run produces zero diff
   (TC2 — CI invariant).
4. `pnpm check` (lint + typecheck + test + build + size-check) returns 0.
5. The PR.md (`docs/plans/wave-3-main/Pre-A1-codex-profile-toml-merge.md`) is
   present in the staged file list at commit time per ADR-0006 D8 strict
   whitelist (PR #1 R2 lesson).
6. `agent-contract.md` is **unchanged** by this PR (verified at review time —
   spot-check `git diff main -- agent-contract.md` returns empty); the locked
   plan's "Modify: agent-contract.md" line was a verification cue, not an edit.

## Out-of-scope (explicitly deferred)

- Auto-validating that the user actually performed the TOML merge on their
  machine. The runbook documents the verification command; enforcement is
  out-of-band (TC1' is recorded for traceability only).
- Splitting `tmp/codex-profiles.toml` into per-profile files, or replacing
  manual merge with a `scripts/merge-codex-profiles.ts` automation. Could
  follow as a Wave 3 cleanup PR if friction warrants; not required to
  unblock Stage A.
- Removing the legacy Wave 1+2 profiles (`code-reviewer`, `pr-gate`) from the
  user's `~/.codex/config.toml`. Wave 3 deliberately keeps `pr-gate` as a
  transitional alias; cleanup is post-Stage-D.
- WE-013 template-literal escape audit beyond the new section. Existing
  escape patterns (renderer lines 14, 24, 25, 32, 35-39) are the reference;
  Pre-A1 only mirrors them.
