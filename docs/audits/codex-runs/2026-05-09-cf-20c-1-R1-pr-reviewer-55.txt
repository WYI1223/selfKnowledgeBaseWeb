   271	- `gridColumn = ${col} / span ${colSpan}`
   272	- `gridRow = row !== undefined ? ${row} / span ${effectiveRowSpan} : span ${effectiveRowSpan}`

   277	`BlockNodeView.tsx` (editor), `mdx-adapter.ts` (light-block read), and the
   278	3 heavy `.astro` wrappers (read). Drift detection is via the shared module
   279	import; any future renderer adding a 4th consumer SHOULD import
   280	`gridPlacementStyle` rather than re-deriving the formula.

   282	`useAutoRowSpan` public surface:
   283	
   284	```ts
   285	export function useAutoRowSpan(
   286	  contentRef: RefObject<HTMLElement | null>,
   287	  rowHeightPx = 48,           // matches --row-h
   288	  gapPx = 14,                  // matches --gap
   289	): number;
   290	```
   291	
   292	The hook returns an integer rowSpan greater than or equal to 1. It implements
   293	ADR-0016 D3's rendering-derived markdown rowSpan behavior: rowSpan is computed
   294	from `scrollHeight` and is not itself a persistent document write. Its 3-stage
   295	抖动收敛 behavior is:
   296	
   297	1. Stage 1: first ResizeObserver event establishes the initial rowSpan.
   298	2. Stage 2: later font, image, and code-fence height changes inside one rAF
   299	   window coalesce into a single render commit.
   300	3. Stage 3: subsequent ResizeObserver events update only when the integer
   301	   rowSpan delta is at least 1; delta 0 is ignored as pixel noise.

   539	## Type variance note (Stage A A3 R3 retrospective; codified Wave 4 B4)
   540	
   541	`registerBlocks` casts 5 of 8 ui-defaults via `XxxUiDefault as unknown as BlockUIDefinition` and leaves the remaining 3 uncast. The asymmetry is structural, not historical: it traces ComponentType contravariance under `exactOptionalPropertyTypes: true`.
   542	
   543	- **5 with cast** (callout / code / image / math / pdf): each
   544	  package's `XxxUiDefault` is typed
   545	  `BlockUIDefinition<typeof XxxCore.propsSchema>` — a NARROW schema
   546	  via `defineUI`'s generic. The narrow schema's
   547	  `EditorView`/`RenderView` is `ComponentType<BlockViewProps&lt;NarrowSchema&gt;>`,
   548	  which is NOT assignable to the registry's wider
   549	  `ComponentType<BlockViewProps&lt;ZodTypeAny&gt;>` due to ComponentType
   550	  contravariance. The cast collapses the variance gap. ESLint's
   551	  `no-unnecessary-type-assertion` does NOT flag these casts because
   552	  the assertion is genuinely required by tsc.
   553	- **3 without cast** (jupyter / nn-viz / agent-flow): each package's
   554	  `XxxUiDefault` resolves through `defineUI` with a wider component
   555	  type signature that already accepts `BlockViewProps&lt;ZodTypeAny&gt;`
   556	  without contravariance issue (verified at A3 EXECUTE 2026-05-01;
   557	  tsc accepts the direct registration). Adding the cast here would
   558	  be a no-op; ESLint's `no-unnecessary-type-assertion` would flag it.
   559	
   560	**Implication**: the 5/3 split is locked-in until the underlying
   561	ui-default package types converge. Future blocks SHOULD pick the
   562	3-camp signature shape (no cast required) when authoring new
   563	ui-defaults; A3 R3 incident notes the asymmetry was first
   564	surfaced when a contributor uniformly cast all 8, which lint then
   565	rejected on the 3 unnecessary-cast cases. The cast-required vs
   566	cast-free behavior is verified at every `pnpm typecheck` run +
   567	`pnpm lint` run on `registerBlocks.ts`; any drift will surface
   568	immediately.
