1. R1 P1 issue resolution (3/3)
----------------------------------------------------------------

[P1-A] runDefaultCommand explicit dispatcher (no dynamic chain access)
  RESOLVED. dispatch.ts:15-42 is a pure switch statement keyed on the
  command-name literal. Every case calls a concrete Tiptap chain method
  with explicit args (e.g. {level: 1|2|3}). default branch returns false
  without invoking the chain (line 39-40).
  Identical pattern in isDefaultCommandActive (line 44-69). No
  chain[name]() dynamic property access remains anywhere in the package.

[P1-B] Heading buttons map to toggleHeading({level: N}) per Tiptap spec
  RESOLVED. dispatch.ts:30,32,34 calls focused.toggleHeading({level: 1|2|3}).run()
  for the three heading button-IDs. Test toolbar-dispatch.test.ts:37-54
  asserts the chain receives 'toggleHeading' (not 'toggleHeading1') with
  args [{level: 1}], [{level: 2}], [{level: 3}] respectively. Bug class
  (silent no-op via dynamic chain['toggleHeading1']()) is no longer
  reachable.

[P1-C] toolbar-dispatch test verifies chain dispatch via mock
  RESOLVED. toolbar-dispatch.test.ts ships 9 tests:
    - 7 dispatch tests (toggleBold; heading levels 1/2/3; bulletList
      + orderedList; italic/strike/code; unknown-cmd fail-safe;
      every defaultToolbarConfig button id is dispatch-routable)
    - 2 isActive tests (correct mark/heading-level args; unknown-cmd
      no-query fail-safe)
  Combined with 5 toolbar-config tests = 14 total. The
  "every default button id is dispatch-routable" test (line 85-92)
  is the load-bearing item: it auto-catches drift between
  defaultToolbarConfig.buttons and the runDefaultCommand switch.
