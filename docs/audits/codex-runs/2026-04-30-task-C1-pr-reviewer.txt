## 3. ARCHITECTURAL CONSISTENCY

### defineCore() omission: MINOR OBSERVATION (not a blocker)

RFC §1 example: export const calloutCore = defineCore({ name: 'callout', ... })
Actual impl:    export const calloutCore: BlockCoreDefinition<typeof propsSchema> = { ... }

defineCore is documented as "a no-op identity helper — equivalent to writing the type
annotation manually." Both patterns are TypeScript-equivalent and produce identical
runtime behavior. The direct annotation is equally cloneable by codex-block-generator.
However, it deviates from the RFC walkthrough. Orchestrator may wish to note this for
C3/C4 clone prompt context. Not a blocker.

### Serialize/parse stub pattern: PASS

serializeCallout and parseCallout expose stable signatures and call
calloutCore.propsSchema.parse() for self-validation. Local type aliases
CalloutTiptapNode / CalloutMdastJsxElement avoid dead-dep on mdx-bridge.
parseCallout guard (node.name !== calloutCore.mdxComponent) is correct defensive
behavior. CONTRACT.md stub designation is accurate and explicit.

  core/index.ts, core/core-definition.ts, core/serialize.ts, core/parse.ts,
  src/__tests__/core.test.ts, __tests__/fixtures/, CONTRACT.md, package.json,
