    47	
    48	### The 8 items
    49	
    50	1. **Field/attribute audit**: After adding a field to a data shape (Zod schema, Pydantic model, TS interface, mdast attrs, etc.), audit every comparator / equality / serialization / canonicalization function that handles this shape. (Wave 1 evidence: instance #4 — `marksEqual` link branch missed `title` when serialize emitted it.)
    51	
    52	2. **Status code audit**: After adding a status code to one HTTP handler (or, generally, an exit/error code to one branch), audit every other handler emitting the same code. (Wave 1 evidence: instance #2 — custom `SkbError` 401 path missed `WWW-Authenticate`.)
    53	
    54	3. **Strictness audit**: After adding `.strict()` (Zod) / `extra='forbid'` (Pydantic) at one level of an object schema, audit every nested object/sub-schema. The strictness setting **does not propagate**; nested objects must opt in independently. (Wave 1 evidence: instance #3 — top-level `.strict()` shipped while nested `frontmatterSchema` still silently stripped unknown keys.)
    55	
    56	4. **Consumer schema audit**: After defining a schema in a single-authority package (e.g. `@skb/content-types/frontmatterSchema`), audit every consumer for inline duplicates or inline redefinitions that should `import` instead. The "deferred swap" pattern — "I'll inline now and import later" — is a contract break that compounds over time. (Wave 1 evidence: instance #6 part 2 — apps/site/content.config.ts inlined `z.object(...)` rather than importing `frontmatterSchema`.)
    57	
    58	5. **Algorithm + runtime constant replication audit**: When an algorithm or runtime constant is replicated outside its authority (e.g. inline FOUC scripts, login challenge derivation, pre-hydration boot logic that cannot import from packages), audit every consumer-side replica for byte-equivalent reproduction. The replica must register a **regression test** that asserts equivalence against the authority across a representative input corpus. (Wave 1 evidence: instance #6 part 1 — FOUC IIFE truthy-coerce vs `getInitialTheme()` strict-whitelist; remediated with `apps/site/src/__tests__/fouc-script.test.ts` 16-row corpus.)
    59	
    60	6. **Sister-file documentation audit**: After updating one CONTRACT.md (or any document that describes a code surface), audit ALL related CONTRACT.md files in the package family for sister-file drift. Two CONTRACT.md files that describe two halves of the same contract must use **identical terminology** for the shared identifiers (function names, schema names, refine predicate names). (Wave 1 evidence: instance #5 — `editor-commands/CONTRACT.md` updated to cite `editBlockInputSchema` while `agent-tools/CONTRACT.md` still referred to the old shape.)
    61	
    62	7. **Exception-scope equivalence audit**: When replicating an algorithm + its exception handling across files, audit BOTH the happy-path semantics AND the `try/catch` scope between authority and replica. Narrow vs wide `try/catch` can produce divergent fall-through behavior even with identical happy-path logic. Specifically: when `localStorage` / `sessionStorage` / `IndexedDB` / `matchMedia` / any browser API in the algorithm path can throw, the `try/catch` MUST wrap ONLY the throwing call, with the fall-through branch (matchMedia / system default / DOM apply) running AFTER the catch handler — not inside it. (Wave 1 evidence: instance #7 — FOUC IIFE wide-scope try/catch swallowed matchMedia exceptions; remediated with narrow try/catch + 2 storage-throws regression tests.)

    64	8. **Authority-document → generated/consumed surface audit**: When updating an authority document (ADR, spec, `agent-contract.md`, runbook, CONVENTIONS) **OR a dependency authority (`package.json`)** that mandates behavior in downstream consumers, audit every consumer-side replica/generated artifact for synchronized update **AND staged-in-the-git-index in the same bundle**. Specifically: an ADR section that says "X file MUST be updated to do Y" requires the same commit to update X and provide a way to verify the synchronization. Generated artifacts (e.g. `docs/review-checklist.md` and `.claude/agents/*.md` derived from `agent-contract.md`; **`pnpm-lock.yaml` derived from `package.json`** — see sub-form C below) MUST be regenerated via the documented codegen step (`pnpm generate:configs` / `pnpm install`) AND **explicitly `git add`'d** so the git **index** (not just the working tree) contains the new content; runbooks (`docs/runbooks/team-operations.md`) MUST be cross-linked; Codex/Claude subagent prompt files MUST embed or reference the new rule.
    65	
    66	   **Operational sequence** (do not skip steps):
    67	   ```bash
    68	   # 1. Edit authority + generator code
    69	   # 2. Run codegen
    70	   pnpm generate:configs
    71	   # 3. Stage regenerated outputs (CRITICAL — see Pitfall below)
    72	   git add <regenerated/path/foo.md> <regenerated/path/bar.md>
    73	   # 4. Verify index reflects content (NOT just working tree):
    74	   git diff --cached --stat -- <regenerated paths>
    75	   #    → expects non-empty diff with the expected line counts
    76	   # 5. Verify idempotence: re-run codegen + confirm working tree matches index:
    77	   pnpm generate:configs
    78	   git status --short -- <regenerated paths>
    79	   #    → expects column-1 'M' (staged) + column-2 blank (working tree clean)
    80	   ```
    81	
    82	   **Pitfall (this is the load-bearing step)**: `git status --short` shows two columns: column 1 is index-vs-HEAD; column 2 is working-tree-vs-index. After running the generator without `git add`, you see `' M'` (space + M) — **working tree differs from index, but index still matches HEAD**. `git commit` only commits the index. Skipping `git add` means the regenerated content is in your working tree but NOT in the next commit. The bundle would land authority + generator-code changes WITHOUT the regenerated outputs, leaving consumers (Wave 2 reviewers reading `.claude/agents/*.md`) at pre-update content. Use `git diff --cached` (not `git status`) as the canonical staging-verification command — `--cached` shows index-vs-HEAD only, which is what `git commit` will produce.
    83	
    84	   **Pitfall extension — `pnpm-lock.yaml` is a generated artifact too (sub-form C below)**: when the authority is `package.json` (any dependency add / remove / version bump / `@types/*` shift), `pnpm install` regenerates `pnpm-lock.yaml` as a deterministic derived artifact. Skipping `git add pnpm-lock.yaml` produces the same class of failure as skipping `git add .claude/agents/*.md`: working tree has the synced lockfile but the **index** still holds HEAD's stale lockfile, so the bundle ships `package.json` ahead of its lockfile. CI runs `pnpm install --frozen-lockfile` from the bundled state, sees the stale lockfile disagreeing with the new `package.json`, and fails install. The same `git diff --cached --stat -- pnpm-lock.yaml` canonical verification applies. (Wave 1 erratum commit `e15ec36`; codified as sub-form C below.)
    85	
    86	   Generated-from-authority files carry their own header comment ("GENERATED FROM agent-contract.md — DO NOT EDIT BY HAND") OR YAML frontmatter declaring authority source — both forms are acceptable. `pnpm-lock.yaml` lacks an explicit header (the format is fixed by pnpm) but is implicitly declared by `pnpm install`'s contract — its authority is `package.json` + the workspace `pnpm-workspace.yaml`.
    87	
    88	   **Wave 1 evidence**: **instance #8** — ADR-0006 v1 commit codified reviewer-prompt mandates but did not update `agent-contract.md` / regenerate `.claude/agents/code-reviewer.md` / regenerate `.claude/agents/pr-gate.md` / cross-link `team-operations.md` / regenerate `docs/review-checklist.md`; pr-gate caught the dogfood failure during R1 review of the close-ceremony bundle, forcing a v2 fix. **instance #12 (sub-form A — pre-regeneration omission)** — v5 bundle updated authority files (`agent-contract.md`, generator code, `team-operations.md` cross-link) but had not run the generator at all post-edit; the 3 regenerated outputs were stale at HEAD content; pr-gate caught this during R2 review, forcing a v6 fix. **instance #12 (sub-form B — staging-vs-working-tree confusion)** — v6 bundle ran the generator (so working tree had new content) but did NOT `git add` the regenerated outputs; the git **index** still held HEAD blob hashes for the 3 generated files; orchestrator confused `git status --short` "M" prefix (working-tree-vs-index) with index-vs-HEAD; pr-gate caught this via `git ls-files --stage` blob-hash comparison during R3 review, forcing the v7 fix that explicitly stages with `git add` + verifies via `git diff --cached`. **instance #12 (sub-form C — lockfile is a generated-from-authority artifact)** — Wave 1 close ceremony commit `e15ec36` ("fix(deps): commit pnpm-lock.yaml for @tailwindcss/typography (lockfile drift)"): the design-tokens erratum (commit `fdc86a8`) added the `@tailwindcss/typography` dependency to `package.json` but did not stage the regenerated `pnpm-lock.yaml`; CI install used the pre-update lockfile, drifted against the new `package.json`, and failed `pnpm install --frozen-lockfile`. Resolution: commit `e15ec36` staged the lockfile separately. Lesson codified: when the authority is `package.json` (any dependency add / remove / version bump), `pnpm-lock.yaml` is the consumer-side generated artifact and must ride the same bundle — the class equivalence to `.claude/agents/*.md` regeneration is exact (deterministic derive + git-index staging required). The four sub-forms of the same item #8 class — pre-regeneration omission, post-regeneration commit-staging confusion, conceptually-correct-but-operationally-incomplete fix, AND lockfile-as-generated-artifact — together motivate the explicit operational sequence and `git diff --cached` canonical verification command codified above.

     1	# @skb/mdx-bridge Contract
     2	
     3	Bidirectional conversion between MDX source and a Tiptap-shaped JSON document.
     4	Wave 1 covers prose only; Wave 2 onward extends the walker for component blocks.
     5	
     6	## Public surface
     7	
     8	- `mdxToTiptap(source: string): TiptapDoc` — parse MDX into a Tiptap-shaped tree
     9	- `tiptapToMdx(doc: TiptapDoc): string` — serialize the Tiptap-shaped tree back to MDX
    10	- `TiptapDoc`, `TiptapNode`, `TiptapMark` — shape types
    11	
    12	`TiptapDoc.frontmatter` is the raw YAML body (without the `---` fences). Block
    13	nodes carry an internal `_mdast` field holding the originating mdast node — this
    14	is what makes byte-equivalent round-trip possible. Editor-only flows that
    15	construct nodes without parsing source can omit `_mdast`; the serializer falls
    16	back to canonical reconstruction.
    17	
    18	## Round-trip invariant
    19	
    20	Two byte-equivalence claims, both enforced on every fixture in
    21	`src/__tests__/fixtures/`:
    22	
    23	1. **Parsed-doc invariant** — for any supported MDX input `S`:
    24	   ```
    25	   tiptapToMdx(mdxToTiptap(S)).trim() === S.trim()
    26	   ```
    27	
    28	2. **Editor-built-doc invariant (canonical reconstruction)** — strip every
    29	   `_mdast` field from a parsed doc to simulate a doc that never went through
    30	   `parse()` (e.g. constructed by Track F's `agent-tools insert_block` /
    31	   `edit_block` or by an editor mutation). The same equivalence must hold:
    32	   ```
    33	   tiptapToMdx(stripMdast(mdxToTiptap(S))).trim() === S.trim()
    34	   ```
    35	
    36	Violating either is a **critical bug**: `mdx-doctor` runs both checks on every
    37	PR that touches this package or any `block-*` package. Either failure blocks
    38	merge.
    39	
    40	Wave 1 baseline (9 prose fixtures × 2 invariants = 18 RTT assertions):
    41	
    42	| Fixture | Coverage |
    43	|---|---|
    44	| `01-paragraph.mdx` | frontmatter + paragraph + plain text |
    45	| `02-heading.mdx` | h1 / h2 + paragraph |
    46	| `03-list.mdx` | bullet list with nested list (loose-spread item) + ordered list |
    47	| `04-quote-and-code.mdx` | blockquote + fenced code (with lang) |
    48	| `05-emphasis-link.mdx` | inline strong / emphasis / inline code / link |
    49	| `06-nested-inline.mdx` | nested inline marks (multi-child strong/emphasis/link) |
    50	| `07-link-with-title.mdx` | link with title attribute (e.g. `[x](url "title")`) |
    51	| `08-bold-with-break.mdx` | hard break (`\\\n`) inside a strong span |
    52	| `09-link-title-comparator.mdx` | same-href links with distinct titles separated by text in a paragraph (adjacent-shape coverage lives in dedicated `marksEqual` regression tests in `round-trip.test.ts`) |
    53

    55	must add at least one fixture exercising its MDX form, and that fixture must

    57	
    58	## Implementation notes
    59	
    60	- Parser pipeline: `unified` + `remark-parse` + `remark-frontmatter` (yaml only)
    61	  + `remark-mdx`. Stay on this pipeline — it is the single source of truth for
    62	  what counts as supported MDX.
    63	- Serializer pipeline: `unified` + `remark-frontmatter` + `remark-mdx` +
    64	  `remark-stringify` with options chosen so that `parse → stringify` is
    65	  idempotent for canonical markdown.
    66	- Block-level Tiptap nodes preserve the originating mdast node on `_mdast` for
    67	  byte-exact passthrough. The serializer **also** runs the canonical
    68	  reconstruction path on the same input via the editor-built-doc invariant
    69	  test, so `_mdast` is a fast-path optimization, not a correctness
    70	  requirement.
    71	- **Inline marks live on each text leaf in outermost-first order.** Tiptap's
    72	  native model — never a wrapper node containing multiple text children. For
    73	  `**bold *and* italic**`, parse emits three text leaves with marks
    74	  `[bold]`, `[bold, italic]`, `[bold]`. The serializer reconstructs nesting
    75	  by greedily grouping adjacent leaves that share the same outermost mark
    76	  and recursing on the group with that mark stripped. This avoids both the
    77	  silent-content-loss class of bug (a wrapper node the serializer doesn't
    78	  recognize) and the over-emit class (one wrapper per leaf →
    79	  `**bold ****and****  italic**`).
    80	- **List looseness** is preserved via `attrs.spread` on both the list and
    81	  each list item, mirroring mdast's `spread` boolean. Without this, the
    82	  blank line in `- item\n\n  - nested` collapses on canonical
    83	  reconstruction.
    84	- **Hard break inside a mark stays inside the mark.** The inline grouper
    85	  treats `hardBreak` as transparent: a run of text leaves sharing the same
    86	  outermost mark may include a `hardBreak` between them, so
    87	  `**a\\\nb**` round-trips as `**a\\\nb**`, not as
    88	  `**a**\\\n**b**`.
    89	- **Link `title`** is preserved on the link mark's `attrs.title` (in
    90	  addition to `attrs.href`). The serializer emits a non-null `title` only
    91	  when the mark carries one — bare links continue to emit `title: null`,
    92	  matching mdast canonical form.
    93	- **`marksEqual` compares link `href` AND `title` verbatim.** Two `link`
    94	  marks with the same href but different titles are treated as DISTINCT —
    95	  the grouper will not merge them under one wrapper. Without the title
    96	  comparison, `[a](url "A")[b](url "B")` would canonicalize to
    97	  `[ab](url "A")` (title B silently dropped + leaves merged); with it,
    98	  both shapes round-trip distinctly. Same-href same-title pairs do still
    99	  merge under one wrapper, identical to the documented adjacent-same-mark
   100	  over-bridge case for `**a****b**` → `**ab**` (Wave 1 acceptable
   101	  canonicalization, Wave 2 trip-hazard catalogued).
   102	
   103	### Fail-loud rule
   104	
   105	Every default branch in parse.ts and serialize.ts MUST throw with a message
   106	of the form `mdx-bridge: unsupported {block,inline,mark} type "<type>". Add
   107	a fixture and a parse + serialize case before introducing this <kind>.`
   108	
   109	Silent fallbacks (returning empty text, dropping siblings, defaulting to a
   110	paragraph stub) are forbidden — they produced two production-class bugs in
   111	earlier review rounds: an `_inlineGroup` wrapper whose siblings vanished,
   112	and a default `wrapMark` branch that dropped the second-onwards leaves of
   113	any unknown mark. The fail-loud rule converts "I forgot to wire up
   114	strikethrough" from "your content disappears" to "your build breaks
   115	loudly." The `mdx-doctor` audit (Wave 2+) and a planned
   116	structure-auditor pass (Erratum 15 candidate) enforce this rule across
   117	the package.
   118	
   119	There are exactly five enforced throw sites today:

Current `registry.ts` also accepts `ZodTypeAny`, not `ZodObject`, with no runtime validation in `registerCore` ([registry.ts:10](/home/weiyi/selfKnowledgeBaseWeb/packages/block-foundation/src/registry.ts:10), [registry.ts:59](/home/weiyi/selfKnowledgeBaseWeb/packages/block-foundation/src/registry.ts:59)). This leaves the first block PR ambiguous.

2. [RFC.md:216](/home/weiyi/selfKnowledgeBaseWeb/packages/block-foundation/RFC.md:216) calls `listCores()` / `listUIs()` defensive-copy behavior a “CONTRACT invariant”, but [CONTRACT.md:14](/home/weiyi/selfKnowledgeBaseWeb/packages/block-foundation/CONTRACT.md:14) through [CONTRACT.md:20](/home/weiyi/selfKnowledgeBaseWeb/packages/block-foundation/CONTRACT.md:20) do not declare it. The implementation does return fresh arrays ([registry.ts:84](/home/weiyi/selfKnowledgeBaseWeb/packages/block-foundation/src/registry.ts:84), [registry.ts:96](/home/weiyi/selfKnowledgeBaseWeb/packages/block-foundation/src/registry.ts:96)), but the sister-doc authority is missing.

3. [RFC.md:53](/home/weiyi/selfKnowledgeBaseWeb/packages/block-foundation/RFC.md:53) makes `.strict()` “mandatory at every nested level”, but `CONTRACT.md` does not declare that invariant, and `BlockCoreDefinition` only requires `ZodTypeAny`. If this is a real block-props rule, it must be promoted into the contract or scoped clearly as a consumer test recommendation.

4. The compile-time error section is not complete for the public surface ([RFC.md:206](/home/weiyi/selfKnowledgeBaseWeb/packages/block-foundation/RFC.md:206)). It omits invalid/missing `name`, `kind`, `mdxComponent`, `coreName`, `uiId`, and `BlockViewProps.content` shape coverage from [registry.ts:4](/home/weiyi/selfKnowledgeBaseWeb/packages/block-foundation/src/registry.ts:4) through [registry.ts:35](/home/weiyi/selfKnowledgeBaseWeb/packages/block-foundation/src/registry.ts:35). Given this RFC will be referenced by all later `block-*` PRs, this is not complete enough.

**CONCERN**
- `defineCore` is described as an identity inference helper ([RFC.md:62](/home/weiyi/selfKnowledgeBaseWeb/packages/block-foundation/RFC.md:62)); `defineUI` is used but not equivalently described. The examples also manually annotate both definitions, so they do not really demonstrate the helper’s inference value.
