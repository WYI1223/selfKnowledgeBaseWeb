    60	(`packages/block-{jupyter,nn-viz,agent-flow}/src/ui-default/*.astro`)
    61	that emit lightweight HTML markup, but these are not consumed by
    62	`apps/site/src/components.ts` — the MDX renderer expects React
    63	components, not Astro components.
    64	
    65	Plan-challenger codex round (2026-05-03; absorbtion table at end of ADR)
    66	raised 12 challenges (7 high-strength) covering package ownership,
    67	dimensions ownership, API surface, CSS ownership, consumer surface
    68	(MDX vs editor split), and operational concerns (unmount guards,
    69	a11y, retry, type strategy, dead-dep). All 12 absorbed; D-list below
    70	reflects post-absorbtion state.

    72	## Decision
    73	
    74	apps/site Wave 4 heavy-block consumption uses a unified
    75	`HeavyBlockBoundary` React wrapper component, hosted in a new
    76	`@skb/heavy-block-boundary` package, applied at the apps/site MDX
    77	componentsMap layer (NOT at editor NodeView path; see D9).
    78	
    79	### D1 — Component API
    80	
    81	```typescript
    82	import type { ComponentType, ReactNode } from 'react';
    83	
    84	// Open extension point: closed for known kinds, branded type for plugins.
    85	export interface HeavyBlockKindRegistry {
    86	  readonly jupyter: 'jupyter';
    87	  readonly 'nn-viz': 'nn-viz';
    88	  readonly 'agent-flow': 'agent-flow';
    89	}
    90	export type HeavyBlockKind =
    91	  | keyof HeavyBlockKindRegistry
    92	  | (string & { readonly __heavyBlockKind?: never });  // intentional widening
    93	
    94	export interface HeavyBlockDimensions {
    95	  readonly width: number;       // CSS px; min-width
    96	  readonly height: number;      // CSS px; min-height
    97	}
    98	
    99	export interface HeavyBlockBoundaryProps<P> {
   100	  readonly kind: HeavyBlockKind;
   101	  readonly dims: HeavyBlockDimensions;
   102	  readonly load: (init?: { signal?: AbortSignal }) => Promise<{ default: ComponentType<P> }>;
   103	  readonly loadingText?: string;          // default: `Loading ${kind}...`
   104	  readonly errorText?: string;            // default: `Failed to load ${kind}`
   105	  readonly retryLabel?: string;           // default: `Retry`
   106	  readonly maxRetries?: number;           // default: 2 (after which retry button disables; per C5 bounded)
   107	  readonly childProps: P;                 // forwarded to loaded component
   108	  readonly fallback?: ReactNode;          // optional override of SSR placeholder
   109	  readonly onLoadError?: (e: unknown, attempt: number) => void;  // telemetry hook
   110	}
   111	```
   112	
   113	Generic `<P>` parameter preserves type safety on `childProps`.
   114	Branded-type widening for `HeavyBlockKind` keeps known-kind autocomplete
   115	while allowing third-party plugin kinds (per C6 absorbtion).
   116	
   117	### D2 — SSR rendering (matches HTML byte-for-byte to hydrated first paint)
   118	
   119	```html
   120	<div
   121	  data-block="<kind>"
   122	  data-deferred="wave-4"
   123	  class="heavy-block-skeleton heavy-block-skeleton--<kind>"
   124	  role="status"
   125	  aria-busy="true"
   126	  style="width:<W>px;min-height:<H>px;..."
   127	>
   128	  <div class="heavy-block-skeleton__frame" aria-hidden="true"></div>
   129	  <div class="heavy-block-skeleton__spinner" aria-hidden="true"></div>
   130	  <div class="heavy-block-skeleton__text" aria-live="polite">{loadingText}</div>
   131	</div>
   132	```
   133	
   134	`min-height` (not fixed `height`) so post-hydration content can grow
   135	without re-shrinking. CSS uses `prefers-reduced-motion` query to skip
   136	spinner animation. Per C2 absorbtion: `role='status'` + `aria-busy`
   137	on container; `aria-live='polite'` ONLY on text element (so dynamic
   138	loadingText/errorText changes are announced; static initial render is
   139	NOT — `polite` queues until next a11y idle).
   140	
   141	### D3 — Hydration behavior + lifecycle (per C1 + C5 absorbtion)
   142	
   143	Pure React `useEffect` + `useState` + `AbortController` pattern:
   144	
   145	1. SSR render = D2 skeleton (matches client first-paint byte-for-byte
   146	   → no hydration mismatch warning)
   147	2. `useEffect` (mount): create `AbortController`; call
   148	   `load({ signal: controller.signal })`; track `attempt` count.
   149	3. **Mount-guard**: a `mountedRef` (or equivalent) ignores late
   150	   resolve/reject after unmount. Late settlement is a no-op (NOT a
   151	   `setState` on unmounted component).
   152	4. On resolve: `setComponent(LoadedComponent)`; clear `aria-busy`.
   153	5. On reject (`!signal.aborted`): set error state; render error
   154	   affordance with retry button (up to `maxRetries`); call
   155	   `onLoadError(err, attempt)` for telemetry.
   156	6. On unmount: `controller.abort()` to cancel in-flight `load()` if
   157	   the implementation honors AbortSignal.
   158	7. On retry click: increment attempt; new AbortController; re-call
   159	   `load({ signal })`. Skeleton state restored during retry.
   160	8. After `maxRetries` exhausted: retry button disabled; error
   161	   announcement persists; user can manually navigate or refresh.
   162	
   163	Render: `<LoadedComponent {...childProps} />` inside same outer `<div>`
   164	(preserves `data-block` + dimensions for layout stability) once load
   165	resolves. **No Astro `client:only` directive needed** — this is pure
   166	React lazy loading inside MDX componentsMap (which is React-only by
   167	Astro design).
   168	
   169	### D4 — Plugin extensibility (per Q5 + C3 absorbtion: split surface)
   170	
   171	**MDX/static render path scope**: `HeavyBlockBoundary` wraps a heavy
   172	block's `RenderView` so that any apps/site MDX consumer or future
   173	static page consumer gets the boundary for free.
   174	
   175	**Editor (Tiptap NodeView) path scope**: editor consumes the heavy
   176	block's `EditorView` directly per `editor-shell` registration —
   177	**does NOT pass through HeavyBlockBoundary by default**. Editor has
   178	different lifecycle (mount/unmount on document edits; user explicitly
   179	opens a heavy block; no SSR concern). If editor wants the boundary
   180	semantics for first-mount lazy load, it opts in by wrapping its
   181	`EditorView` registration manually.
   182	
   183	Each heavy block package exports both:
   184	- `<Kind>RenderView` — the renderer (may be wrapped externally by
   185	  consumer using `HeavyBlockBoundary`)
   186	- `<Kind>EditorView` — the editor NodeView (stays unwrapped unless
   187	  caller opts in)
   188	
   189	Future heavy block packages (e.g., `@skb/block-3d-graph`) contribute:
   190	- `<Kind>RenderView` (heavy)
   191	- `heavyBoundaryDimensions: HeavyBlockDimensions` (per Q2 absorbtion;
   192	  see D5)
   193	- Optional pre-wrapped helper export `<Kind>RenderViewWithBoundary`
   194	  for consumers that want a one-liner
   195	
   196	apps/site composition continues to be the integration point for the
   197	3 first consumers: `apps/site/src/components.ts` componentsMap.
   198	
   199	### D5 — Dimensions ownership (per Q2 absorbtion)
   200	
   201	**Per-block declaration** (each heavy block ui-default package owns
   202	the value):
   203	
   204	```typescript
   205	// packages/block-jupyter/src/ui-default/jupyter.ui.ts

   213

   285	### D7 — Package ownership (per Q1 absorbtion)
   286	
   287	**NEW package: `@skb/heavy-block-boundary`** (NOT in `block-foundation`).

   289	Rationale:
   290	- `block-foundation` today has zero React deps (only types/registry).

   293	- `apps/site` is wrong host for a reusable runtime boundary that

   295	- New package isolates the runtime concern + can be marked `peer` dep
   296	  on React for environments not bundling apps/site (e.g., editor-only
   297	  consumers, third-party block packages).
   298	
   299	Package shape (Stage A authoring):
   300	- `packages/heavy-block-boundary/package.json` — `peerDependencies:
   301	  { react: ">=18", react-dom: ">=18" }`; optional `@skb/design-tokens`
   302	  for CSS variable inheritance
   303	- `packages/heavy-block-boundary/CONTRACT.md` — public surface (the API
   304	  defined in D1) + invariants (SSR/hydration byte-equivalence, mount
   305	  guard, retry semantics, etc.)
   306	- `packages/heavy-block-boundary/src/HeavyBlockBoundary.tsx` —
   307	  implementation
   308	- `packages/heavy-block-boundary/src/heavy-block-skeleton.css` — D6 CSS

   344	### D9 — Editor consumer scope (per C3 absorbtion: explicit non-coverage)
   345	
   346	Editor (Tiptap NodeView) consumption of heavy blocks is **out of scope**
   347	for ADR-0014. `editor-shell` continues to register heavy block
   348	`EditorView` exports directly (per Wave 3 A3 registerBlocks pattern,
   349	unchanged). Reasons:
   350	
   351	- Editor lifecycle differs from MDX render path (mount/unmount on doc
   352	  edits; user explicitly clicks a heavy block to open it).
   353	- Editor has no SSR concern (Astro doesn't render the editor).
   354	- Layout-shift concern is moot (editor canvas has its own layout
   355	  authority).
   356	- If a future requirement emerges to lazy-load heavy blocks in
   357	  editor too, that's a separate ADR (ADR-0014 amendment or ADR-0015).
   358

   360	the boundary to "MDX componentsMap consumption" so editor symmetry
   361	isn't accidentally broken.

   363	## Acceptance criteria (Wave 4 Stage A implementation must satisfy)
   364	
   365	Per C4 + C5 absorbtion, hardened test matrix:
   366	
   367	1. **Component lives in single package**: `@skb/heavy-block-boundary`
   368	   per D7 (NOT `block-foundation`).
   369	2. **Type-safe API**: `HeavyBlockBoundary<P>` props per D1; vitest type
   370	   test (or `tsc --noEmit` on a fixture) verifies generic `P` + branded
   371	   `HeavyBlockKind` widening.
   372	3. **SSR/hydration byte-equivalence (C4 #1)**: vitest test renders
   373	   component to string with React's `renderToString`; asserts initial
   374	   client mount produces identical DOM (no hydration mismatch warning
   375	   per React's `consoleError` mock). Skeleton CSS classes + `data-*`
   376	   attributes + dimensions match exactly.
   377	4. **Exact CSS class/size/style at first paint (C4 #2)**: vitest +
   378	   `getBoundingClientRect()` (or DOM string match with `style="..."`)
   379	   asserts width/min-height set per `dims` prop.
   380	5. **No width/height regression at T0/T1 (C4 #3, gatekeeper smoke #10
   381	   layout-shift core mandate)**: playwright spec compares
   382	   `getBoundingClientRect()` immediately after first render (T0) vs
   383	   after hydration completes (T1, awaited via `data-loaded` attribute
   384	   or similar). Allowed delta: `<= 5px` for spinner→content
   385	   transition; outer container width must be IDENTICAL.
   386	6. **Successful load path (C4 #4a)**: vitest test simulates fast
   387	   `load()` resolve; asserts `<LoadedComponent {...childProps} />`
   388	   renders with `data-loaded="true"` after `useEffect` settles.
   389	7. **Rejected load path (C4 #4b + C5)**: vitest test simulates
   390	   `load()` reject; asserts error UI renders with retry button + error
   391	   text + `aria-busy="false"` + `onLoadError(err, 1)` called.
   392	8. **Retry path (C5)**: vitest test clicks retry button; asserts new
   393	   `load()` invocation with NEW AbortSignal + skeleton restored
   394	   between attempts + `attempt` count incremented in `onLoadError`.
   395	9. **`maxRetries` bound (C5)**: vitest test rejects N+1 times where
   396	   N=`maxRetries`; asserts retry button disabled + telemetry call
   397	   for each attempt. Default `maxRetries=2` honored.
   398	10. **Mount guard (C1)**: vitest test mounts component; calls
   399	    `unmount()` BEFORE `load()` resolves; asserts no React state
   400	    update warning + no `setState` after unmount.
   401	11. **AbortSignal propagation (C1)**: vitest test verifies `load()` is
   402	    called with `{ signal }` arg + `signal.aborted=true` after unmount.
   403	12. **A11y semantics (C2)**: vitest test asserts `role="status"` +
   404	    `aria-busy="true"` (during load) → `aria-busy="false"` (after).
   405	    `aria-live="polite"` only on text element. Spinner `aria-hidden`.
   406	13. **Plugin extensibility test (D4)**: vitest test wraps a fake
   407	    heavy block via the API + verifies skeleton + load flow for an
   408	    unregistered branded kind (e.g., `kind: '3d-graph'`).
   409	14. **prefers-reduced-motion handled**: vitest CSS-in-JS test asserts
   410	    `@media (prefers-reduced-motion: reduce)` rule present + spinner
   411	    animation disabled in matching env.
   412	15. **Dimensions sourced from heavy block (D5)**: contract test
   413	    confirms `apps/site/src/components.ts` imports
   414	    `heavyBoundaryDimensions` from each heavy block package (NOT
   415	    inline literals).

   417	## Consequences
   418	
   419	### Positive
   420	- Zero layout shift between SSR and hydrated state (gatekeeper smoke #10 closed)
   421	- Visual clarity (user sees "this is a block")
   422	- Plugin-extensible to future heavy blocks (per gatekeeper directive + Q5 absorbtion)
   423	- Phase 1 + Phase 2 chunking (`apps/site/astro.config.mjs` `manualChunks`) unchanged; HeavyBlockBoundary uses dynamic `import()` which Vite respects
   424	- Pure React; no Astro `client:only` directive needed (compatible with MDX componentsMap)
   425	- Network failure UX is first-class (retry + telemetry; per C5)
   426	- Mount guard prevents stale-resolve setState bugs (per C1)
   427	- A11y semantics follow MDN/WAI-ARIA loading-region best practices (per C2)
   428	- Editor consumer surface remains unchanged (per C3); D9 explicit out-of-scope language
   429	
   430	### Negative
   431	- New package surface (`@skb/heavy-block-boundary`) — increments workspace count from 21 → 22
   432	- New W4-1 invariant in `block-foundation/CONTRACT.md` (cross-package surface contract)
   433	- Each heavy block package gains 1 export (`heavyBoundaryDimensions`); minor surface additions
   434	- CSS authoring co-located in new package (acceptable per Q4)
   435	
   436	### Neutral / explicit acknowledgements
   437	- Does NOT change ADR-0009 BlockKind union; `viz` kind unchanged
   438	- Does NOT change MDX componentsMap injection mechanism (still pure React per Astro design)
   439	- Does NOT use Astro `client:only` directive (incompatible with MDX static componentsMap)
   440	- Does NOT replace `*.astro` variants in heavy block packages (those remain available for direct Astro integration when not in MDX context)
   441	- Does NOT mandate editor NodeView wrap (D9 out-of-scope)

   443	## Alternatives considered
   444	
   445	### A. block-foundation hosts HeavyBlockBoundary
   446	
   447	Rejected per Q1: block-foundation has zero React deps; adding a React
   448	component changes its shape + introduces React peer-dep. Forks separate
   449	"heavy block runtime" concern from "block schema/registry" concern.
   450	
   451	### B. apps/site hosts HeavyBlockBoundary (no new package)
   452	
   453	Rejected per Q1: localizes to consumer; breaks plugin-extensibility
   454	intent. Each future heavy block consumer would re-author the boundary.
   455	New package is the right shape per gatekeeper directive
   456	"为未来插件 / 新 block 类型快速接入预留".
   457	
   458	### C. Astro client:only on `<Jupyter.astro>` directly
   459	
   460	Rejected: requires bridging from MDX componentsMap (React) to Astro
   461	components — non-trivial in current Astro architecture. Pure-React
   462	HeavyBlockBoundary path is more idiomatic for MDX consumers.
   463	
   464	### D. React.lazy + Suspense (idiomatic)
   465	
   466	Rejected per Q3: doesn't integrate cleanly with the SSR-skeleton-must-
   467	match-byte-for-byte constraint, and gives less control over retry +
   468	mount-guard semantics. Custom useEffect/useState + AbortController
   469	pattern is the right shape for our constraints. Suspense remains
   470	viable as a future internal refactor if React server components or
   471	streaming SSR semantics evolve.
   472	
   473	### E. Centralized `dimensions` map in ADR or boundary package
   474	
   475	Rejected per Q2: single-source-of-truth violation; drifts as widths
   476	change. Per-block ownership (D5) keeps invariant in the natural place
   477	(each block knows its own ideal dimensions).
   478	
   479	### F. Open `string` HeavyBlockKind type
   480	
   481	Rejected per C6: effectively `string`, loses autocomplete on known
   482	kinds. Branded-type widening (D1) preserves both compile-time
   483	autocomplete AND plugin extensibility.

    44	## Decision
    45	
    46	Adopt an **8-point asymmetry-audit checklist** as a mandatory part of `code-reviewer` (Codex 5.3-spark, default cheap) and `pr-gate` (Codex 5.5, deep) review prompts. Reviewers MUST work through every applicable item before declaring PASS.
    47	
    48	### The 8 items
    49	
    50	1. **Field/attribute audit**: After adding a field to a data shape (Zod schema, Pydantic model, TS interface, mdast attrs, etc.), audit every comparator / equality / serialization / canonicalization function that handles this shape. (Wave 1 evidence: instance #4 — `marksEqual` link branch missed `title` when serialize emitted it.)
    51	
    52	2. **Status code audit**: After adding a status code to one HTTP handler (or, generally, an exit/error code to one branch), audit every other handler emitting the same code. RFC-mandated headers (RFC 7235 `WWW-Authenticate` on 401, RFC 7231 `Allow` on 405) attach to **the status code itself**, not the framework code path that emitted it. (Wave 1 evidence: instance #2 — custom `SkbError` 401 path missed `WWW-Authenticate`.)
    53	
    54	3. **Strictness audit**: After adding `.strict()` (Zod) / `extra='forbid'` (Pydantic) at one level of an object schema, audit every nested object/sub-schema. The strictness setting **does not propagate**; nested objects must opt in independently. (Wave 1 evidence: instance #3 — top-level `.strict()` shipped while nested `frontmatterSchema` still silently stripped unknown keys.)
    55	
    56	4. **Consumer schema audit**: After defining a schema in a single-authority package (e.g. `@skb/content-types/frontmatterSchema`), audit every consumer for inline duplicates or inline redefinitions that should `import` instead. The "deferred swap" pattern — "I'll inline now and import later" — is a contract break that compounds over time. (Wave 1 evidence: instance #6 part 2 — apps/site/content.config.ts inlined `z.object(...)` rather than importing `frontmatterSchema`.)
    57	
    58	5. **Algorithm + runtime constant replication audit**: When an algorithm or runtime constant is replicated outside its authority (e.g. inline FOUC scripts, login challenge derivation, pre-hydration boot logic that cannot import from packages), audit every consumer-side replica for byte-equivalent reproduction. The replica must register a **regression test** that asserts equivalence against the authority across a representative input corpus. (Wave 1 evidence: instance #6 part 1 — FOUC IIFE truthy-coerce vs `getInitialTheme()` strict-whitelist; remediated with `apps/site/src/__tests__/fouc-script.test.ts` 16-row corpus.)
    59	
    60	6. **Sister-file documentation audit**: After updating one CONTRACT.md (or any document that describes a code surface), audit ALL related CONTRACT.md files in the package family for sister-file drift. Two CONTRACT.md files that describe two halves of the same contract must use **identical terminology** for the shared identifiers (function names, schema names, refine predicate names). (Wave 1 evidence: instance #5 — `editor-commands/CONTRACT.md` updated to cite `editBlockInputSchema` while `agent-tools/CONTRACT.md` still referred to the old shape.)
    61	
    62	7. **Exception-scope equivalence audit**: When replicating an algorithm + its exception handling across files, audit BOTH the happy-path semantics AND the `try/catch` scope between authority and replica. Narrow vs wide `try/catch` can produce divergent fall-through behavior even with identical happy-path logic. Specifically: when `localStorage` / `sessionStorage` / `IndexedDB` / `matchMedia` / any browser API in the algorithm path can throw, the `try/catch` MUST wrap ONLY the throwing call, with the fall-through branch (matchMedia / system default / DOM apply) running AFTER the catch handler — not inside it. (Wave 1 evidence: instance #7 — FOUC IIFE wide-scope try/catch swallowed matchMedia exceptions; remediated with narrow try/catch + 2 storage-throws regression tests.)
    63	
    64	8. **Authority-document → generated/consumed surface audit**: When updating an authority document (ADR, spec, `agent-contract.md`, runbook, CONVENTIONS) **OR a dependency authority (`package.json`)** that mandates behavior in downstream consumers, audit every consumer-side replica/generated artifact for synchronized update **AND staged-in-the-git-index in the same bundle**. Specifically: an ADR section that says "X file MUST be updated to do Y" requires the same commit to update X and provide a way to verify the synchronization. Generated artifacts (e.g. `docs/review-checklist.md` and `.claude/agents/*.md` derived from `agent-contract.md`; **`pnpm-lock.yaml` derived from `package.json`** — see sub-form C below) MUST be regenerated via the documented codegen step (`pnpm generate:configs` / `pnpm install`) AND **explicitly `git add`'d** so the git **index** (not just the working tree) contains the new content; runbooks (`docs/runbooks/team-operations.md`) MUST be cross-linked; Codex/Claude subagent prompt files MUST embed or reference the new rule.
    65	
    66	   **Operational sequence** (do not skip steps):
    67	   ```bash
    68	   # 1. Edit authority + generator code
    69	   # 2. Run codegen
    70	   pnpm generate:configs
    71	   # 3. Stage regenerated outputs (CRITICAL — see Pitfall below)
    72	   git add <regenerated/path/foo.md> <regenerated/path/bar.md>
    73	   # 4. Verify index reflects content (NOT just working tree):
    74	   git diff --cached --stat -- <regenerated paths>
    75	   #    → expects non-empty diff with the expected line counts
    76	   # 5. Verify idempotence: re-run codegen + confirm working tree matches index:
    77	   pnpm generate:configs
    78	   git status --short -- <regenerated paths>
    79	   #    → expects column-1 'M' (staged) + column-2 blank (working tree clean)
    80	   ```
    81	
    82	   **Pitfall (this is the load-bearing step)**: `git status --short` shows two columns: column 1 is index-vs-HEAD; column 2 is working-tree-vs-index. After running the generator without `git add`, you see `' M'` (space + M) — **working tree differs from index, but index still matches HEAD**. `git commit` only commits the index. Skipping `git add` means the regenerated content is in your working tree but NOT in the next commit. The bundle would land authority + generator-code changes WITHOUT the regenerated outputs, leaving consumers (Wave 2 reviewers reading `.claude/agents/*.md`) at pre-update content. Use `git diff --cached` (not `git status`) as the canonical staging-verification command — `--cached` shows index-vs-HEAD only, which is what `git commit` will produce.
    83	
    84	   **Pitfall extension — `pnpm-lock.yaml` is a generated artifact too (sub-form C below)**: when the authority is `package.json` (any dependency add / remove / version bump / `@types/*` shift), `pnpm install` regenerates `pnpm-lock.yaml` as a deterministic derived artifact. Skipping `git add pnpm-lock.yaml` produces the same class of failure as skipping `git add .claude/agents/*.md`: working tree has the synced lockfile but the **index** still holds HEAD's stale lockfile, so the bundle ships `package.json` ahead of its lockfile. CI runs `pnpm install --frozen-lockfile` from the bundled state, sees the stale lockfile disagreeing with the new `package.json`, and fails install. The same `git diff --cached --stat -- pnpm-lock.yaml` canonical verification applies. (Wave 1 erratum commit `e15ec36`; codified as sub-form C below.)
    85	
    86	   Generated-from-authority files carry their own header comment ("GENERATED FROM agent-contract.md — DO NOT EDIT BY HAND") OR YAML frontmatter declaring authority source — both forms are acceptable. `pnpm-lock.yaml` lacks an explicit header (the format is fixed by pnpm) but is implicitly declared by `pnpm install`'s contract — its authority is `package.json` + the workspace `pnpm-workspace.yaml`.
    87	
    88	   **Wave 1 evidence**: **instance #8** — ADR-0006 v1 commit codified reviewer-prompt mandates but did not update `agent-contract.md` / regenerate `.claude/agents/code-reviewer.md` / regenerate `.claude/agents/pr-gate.md` / cross-link `team-operations.md` / regenerate `docs/review-checklist.md`; pr-gate caught the dogfood failure during R1 review of the close-ceremony bundle, forcing a v2 fix. **instance #12 (sub-form A — pre-regeneration omission)** — v5 bundle updated authority files (`agent-contract.md`, generator code, `team-operations.md` cross-link) but had not run the generator at all post-edit; the 3 regenerated outputs were stale at HEAD content; pr-gate caught this during R2 review, forcing a v6 fix. **instance #12 (sub-form B — staging-vs-working-tree confusion)** — v6 bundle ran the generator (so working tree had new content) but did NOT `git add` the regenerated outputs; the git **index** still held HEAD blob hashes for the 3 generated files; orchestrator confused `git status --short` "M" prefix (working-tree-vs-index) with index-vs-HEAD; pr-gate caught this via `git ls-files --stage` blob-hash comparison during R3 review, forcing the v7 fix that explicitly stages with `git add` + verifies via `git diff --cached`. **instance #12 (sub-form C — lockfile is a generated-from-authority artifact)** — Wave 1 close ceremony commit `e15ec36` ("fix(deps): commit pnpm-lock.yaml for @tailwindcss/typography (lockfile drift)"): the design-tokens erratum (commit `fdc86a8`) added the `@tailwindcss/typography` dependency to `package.json` but did not stage the regenerated `pnpm-lock.yaml`; CI install used the pre-update lockfile, drifted against the new `package.json`, and failed `pnpm install --frozen-lockfile`. Resolution: commit `e15ec36` staged the lockfile separately. Lesson codified: when the authority is `package.json` (any dependency add / remove / version bump), `pnpm-lock.yaml` is the consumer-side generated artifact and must ride the same bundle — the class equivalence to `.claude/agents/*.md` regeneration is exact (deterministic derive + git-index staging required). The four sub-forms of the same item #8 class — pre-regeneration omission, post-regeneration commit-staging confusion, conceptually-correct-but-operationally-incomplete fix, AND lockfile-as-generated-artifact — together motivate the explicit operational sequence and `git diff --cached` canonical verification command codified above.

docs/decisions/ADR-0006-asymmetry-audit-checklist.md:82:   **Pitfall (this is the load-bearing step)**: `git status --short` shows two columns: column 1 is index-vs-HEAD; column 2 is working-tree-vs-index. After running the generator without `git add`, you see `' M'` (space + M) — **working tree differs from index, but index still matches HEAD**. `git commit` only commits the index. Skipping `git add` means the regenerated content is in your working tree but NOT in the next commit. The bundle would land authority + generator-code changes WITHOUT the regenerated outputs, leaving consumers (Wave 2 reviewers reading `.claude/agents/*.md`) at pre-update content. Use `git diff --cached` (not `git status`) as the canonical staging-verification command — `--cached` shows index-vs-HEAD only, which is what `git commit` will produce.
docs/decisions/ADR-0006-asymmetry-audit-checklist.md:84:   **Pitfall extension — `pnpm-lock.yaml` is a generated artifact too (sub-form C below)**: when the authority is `package.json` (any dependency add / remove / version bump / `@types/*` shift), `pnpm install` regenerates `pnpm-lock.yaml` as a deterministic derived artifact. CI runs `pnpm install --frozen-lockfile` from the bundled state, sees the stale lockfile disagreeing with the new `package.json`, and fails install.
