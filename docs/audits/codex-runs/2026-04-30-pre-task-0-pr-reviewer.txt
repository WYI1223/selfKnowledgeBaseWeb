Rationale for accepting:
  1. **Authority-vs-history separation**: Post-ADR-0007 D5, the YAML in agent-contract.md IS the authority. Spec §3.1 is descriptive prose. Bundling a prose rewrite with the authority transition mixes two review concerns (does the YAML/code restructure work? vs does the prose accurately describe it?).

Adding a multi-section spec rewrite of §3.1 + §3.2 + diagram updates would inflate the bundle and slow R2 fix iteration loops (already 3 review rounds).
  3. **Audit-trail consistency**: The changelog row update keeps the spec's audit log current; readers hitting the stale §3.1 narrative can follow the changelog forward to the deferred PR.
  4. **Reviewer chain capacity**: pr-gate's R2 PASS report is calibrated against this bundle scope. Expanding scope post-PASS would require re-review.

Risk acknowledged:
  - Until the deferred PR lands, anyone reading §3.1 narrative finds an outdated "27 agents" story. Mitigation: the changelog row + ADR-0007 are both authoritative pointers to the new model.
  - This deferral creates a "must follow up" obligation. Recommend the orchestrator track this as a follow-up PR before Wave 2 actual work tasks begin (ADR-0007 §371 requires "Wave 2 Pre-Task 0 必须先于 Wave 2 实际工作 task" — this PR satisfies that, but the deferred spec rewrite should land in the same Wave 2 prep window).
