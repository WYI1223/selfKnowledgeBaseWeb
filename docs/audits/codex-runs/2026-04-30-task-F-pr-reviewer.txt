BLOCKING #1: KernelImportError silently swallowed in startSession (item #7)

Location: packages/kernel-pyodide/src/adapter.ts:33-37

```ts
} catch (cause) {
  if (cause instanceof KernelStartupError) throw cause;
  throw new KernelStartupError('PyodideAdapter.startSession failed', { cause });
}
```

createDefaultHostFactory.create() (boot.ts:33-39) deliberately throws KernelImportError for loadPackage failures (distinct from KernelStartupError = Pyodide binary load failure). adapter.ts catch re-wraps every non-KernelStartupError into KernelStartupError, silently destroying the KernelImportError class.

Spec violation:
1. kernel-pyodide/CONTRACT.md:32-33 documents KernelImportError as distinct typed throw surface
2. kernel-adapter/CONTRACT.md:29 mandates subclasses MUST be distinguishable
3. Wave 3 block-jupyter retry logic needs to distinguish 'Pyodide load fail' vs 'lib install fail'

Fix:
```ts
} catch (cause) {
  if (cause instanceof KernelError) throw cause;
  throw new KernelStartupError('PyodideAdapter.startSession failed', { cause });
}
```

BLOCKING #2: session.ts sentinel 'runError !== undefined' unsound for Promise.reject(undefined) (item #7)

Location: session.ts:49, 78

If host.runCode rejects with undefined (Promise.reject() with no arg, valid JS), runError stays undefined → sentinel check false → status:idle emitted with no error event. Consumer sees busy→idle, indistinguishable from successful void execution.

Fix: boolean sentinel
```ts
let runError: unknown;
let hasRunError = false;
// ...
.catch((err) => { runError = err; hasRunError = true; });
// ...
if (hasRunError) yield toErrorEvent(runError);
```
+ add test case for Promise.reject(undefined).
