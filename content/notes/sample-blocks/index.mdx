This page is the Wave 2 close acceptance criterion (Z0). It exercises every component-block
package shipped in Wave 2 by instantiating one or more concrete examples with PascalCase MDX
components. Routing of MDX → React components is Wave 3 `mdx-bridge` work; here we author
content that conforms to each block's `propsSchema` exactly.

**Note on `draft: true`**: this fixture authors block-component MDX content but Astro cannot
yet resolve the 8 PascalCase components (AgentFlow / NnViz / Jupyter / Pdf / Math / Image /
Code / Callout). Wave 3 mdx-bridge integration will register the BlockRegistry → MDX component
map in `apps/site`, after which `draft` flips back to `false`. See ADR-0010 D7 deferred #2.

## Callout

`@skb/block-callout` — variants: `note | tip | warning | danger`. Each variant is an
independent semantic flavor; `title` is optional.

{/* fixture-13: callout note */}
<Callout variant="note" title="Sampler scope">
  This is the Wave 2 sampler page. Eight component-block packages are exercised below.
</Callout>

<Callout variant="tip">
  Tip variants drop the title to verify the optional prop path.
</Callout>

{/* fixture-14: callout warning + danger pair */}
<Callout variant="warning" title="Wave 3 deferred">
  apps/site cannot yet render these components — the BlockRegistry → MDX integration lands
  with `mdx-bridge` in Wave 3.
</Callout>

<Callout variant="danger" title="Strict props">
  Every block uses `.strict()` zod schemas; unknown props will fail validation once routed.
</Callout>

## Code

`@skb/block-code` — `language` is required, `code` is the source string, `showLineNumbers`
defaults `true`. The block is `.strict()`, so the code body is passed as a prop, not as MDX
children.

{/* fixture-15: code python */}
<Code
  language="python"
  code={`def fibonacci(n: int) -> int:
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a


print(fibonacci(10))  # 55
`}
/>

## Image

`@skb/block-image` — `src` and `alt` required; `width`/`height` are optional positive
integers. The schema has no `caption` field, so descriptive prose is rendered alongside the
component.

{/* fixture-16a: image small */}
<Image src="/sample-assets/diagram-small.png" alt="Small architecture diagram" width={320} height={180} />

{/* fixture-16b: image with surrounding caption prose */}
<Image src="/sample-assets/figure-1.png" alt="Figure 1 — block-foundation registration flow" />

in surrounding MDX prose, not in props (ADR-0006: schema is the contract).

## Math

`@skb/block-math` — `expression` is the LaTeX source; `display` toggles inline vs. block
mode (defaults to inline).

Inline math appears mid-sentence:
{/* fixture-17a: math inline */}
<Math expression="e^{i\pi} + 1 = 0" />
— Euler's identity.

Display math stands alone:
{/* fixture-17b: math display */}
<Math expression="\int_{-\infty}^{\infty} e^{-x^{2}} \, dx = \sqrt{\pi}" display />

## Pdf

`@skb/block-pdf` — `src` is the PDF URL, `page` is a 1-indexed page integer (default 1),
`searchable` toggles text-layer extraction (default `false`).

{/* fixture-18a: pdf basic */}
<Pdf src="/sample-assets/whitepaper.pdf" page={1} />

{/* fixture-18b: pdf searchable */}
<Pdf src="/sample-assets/whitepaper.pdf" page={3} searchable />

## Jupyter

`@skb/block-jupyter` — wraps a JupyterLite kernel via the `kernel-pyodide` adapter. `code`
is the cell source, `libraries` declares pip dependencies, `runOnLoad` auto-executes on
mount.

{/* fixture-19: jupyter numpy snippet */}
<Jupyter
  code={`import numpy as np

x = np.linspace(0, 2 * np.pi, 100)
y = np.sin(x)
print(f"y[0]={y[0]:.4f}, y[-1]={y[-1]:.4f}")
`}
  runOnLoad
  showLineNumbers
  libraries={["numpy"]}
/>

## NnViz

`@skb/block-nn-viz` — renders a layer-stack topology. `modelUrl` is required even when
inline `layers` are provided (the URL is the Wave 3 hot-load source). Layers are strict
objects: `{name, units, activation}`.

{/* fixture-20: nn-viz simple model topology */}
<NnViz
  modelUrl="/sample-assets/models/mlp-mnist.json"
  layers={[
    { name: "input", units: 784, activation: "linear" },
    { name: "hidden-1", units: 128, activation: "relu" },
    { name: "hidden-2", units: 64, activation: "relu" },
    { name: "output", units: 10, activation: "softmax" },
  ]}
  showWeights
/>

## AgentFlow

`@skb/block-agent-flow` — directed-graph visualization built on React Flow. Node `type`
is one of `agent | tool | memory | router`. Edges carry `id`, `source`, `target`, and an
optional `label`. `interactive` defaults to `true`.

{/* fixture-21: agent-flow 3-node + 2-edge graph */}
<AgentFlow
  nodes={[
    { id: "n1", label: "Planner", type: "agent", position: { x: 0, y: 0 } },
    { id: "n2", label: "Search", type: "tool", position: { x: 200, y: 0 } },
    { id: "n3", label: "Scratchpad", type: "memory", position: { x: 100, y: 120 } },
  ]}
  edges={[
    { id: "e1", source: "n1", target: "n2", label: "query" },
    { id: "e2", source: "n2", target: "n3", label: "cache" },
  ]}
  interactive
/>
